# Arı Kaynak — Corrections Policy

## Principle

Errors get corrected in the open. A published file is not treated as sacred — it's treated as a claim we're willing to defend, and willing to fix.

## How to report a possible error

Open an issue on the public repository: https://github.com/nitrate07/Blog/issues

Include:
- The file number and URL
- What you believe is incorrect
- A source, if you have one, that supports the correction

## How corrections are handled

**Factual errors** (a misstated number, a misattributed study, an incorrect DOI/PMID, a mischaracterized study type) are corrected directly in the file. The correction is noted at the bottom of the article body, below the verdict, in the following form:

> **Correction (date):** [what was wrong] → [what it now says]. [Brief reason.]

**Source changes** (the underlying study is retracted, updated, or a stronger/newer study changes the picture) trigger a re-evaluation of the verdict itself, not just a footnote. If the verdict changes, the stamp is updated and the correction note explains why.

**Verdict changes** are never made silently. If a file's stamp changes after publication, the correction note says so explicitly, including the original verdict.

## What is NOT a silent edit

The following are corrections and are always logged:
- Any change to a cited number, date, author name, journal, DOI, or PMID
- Any change to the verdict stamp
- Any change that alters what a study is claimed to have found

## What is a normal edit (not logged as a correction)

- Typo fixes, grammar, formatting
- Adding a "Related case files" link to a newer, related investigation
- SEO/metadata updates that don't change the article's factual content

## Timeliness

Corrections are addressed as soon as they're verified — this is a small, independently run publication without a formal editorial desk, so there's no fixed SLA, but factual errors are treated as a priority over new content.
